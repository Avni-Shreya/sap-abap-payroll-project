Overview

What this project does and why it's built this way.

This project automates the core of payroll administration: maintaining employee and salary records, running monthly payroll calculations, generating payslips, and reporting on payroll history. It's built as a single connected system rather than isolated exercises — the Data Dictionary tables feed the reports, the reports feed the OOABAP business logic, and the Module Pool screens tie it all together behind one custom transaction code.

Features

Core functionality plus a set of extensions that go beyond a typical training exercise.

Employee Management

Add, display, update, and delete employee records through a dialog screen.

Salary Management

Maintain salary components with a referential check against the employee master.

Payroll Processing

Calculates Gross Pay and Net Pay for every active employee, with duplicate-run protection.

Payroll Reporting

ALV report with department filters and a Net Pay totals row.

Payslip Generation

Smart Form payslip per employee, runnable individually or as a scheduled batch job.

OOABAP Design

Employee and Manager classes with inheritance and bonus calculation logic.

CDS View

A reusable data model for reporting, ready for future OData/Fiori exposure.

Custom Exceptions

A dedicated exception class hierarchy instead of scattered return-code checks.

BAdI Extension Point

Bonus rules can be customized per department without touching core logic.

Automated Testing

ABAP Unit tests covering the bonus calculation logic.

Authorization Object

Restricts payroll data visibility by department.

System Integration

An RFC-enabled function module exposing employee data to external systems.

Architecture

How the transaction code, screens, and background processes connect.

ZPAYROLL (transaction code) └── ZPMS_MAIN_NAV, Screen 0100 (main navigation) ├── Employee Management → ZPMS_EMP tcode → CRUD dialog screen ├── Salary Management → ZPMS_SAL tcode → CRUD dialog screen ├── Payroll Processing → ZPMS_PAYROLL_PROCESS (batch calculation) └── Payroll Report → ZPMS_PAYROLL_RPT (ALV, totals row) Supporting layer ├── ZCL_EMPLOYEE / ZCL_MANAGER (OOABAP business logic) ├── ZCDS_EMP_DISPLAY (CDS view) ├── ZCX_PAYROLL_EXCEPTION (error handling) ├── ZBADI_PAYROLL_BONUS (extensibility) ├── ZFM_GET_EMPLOYEE_DETAILS (RFC integration) └── ZSF_PAYSLIP (Smart Form)

Deployment

Build order inside an SAP system. Full detail in README.md.

  1. Data Dictionary tables (SE11)Build and activate ZPMS_EMP_MST, ZPMS_SAL_MST, ZPMS_PAY_TRN, ZEMP_MASTER, ZDEPT_MASTER.
  2. Sample dataRun the loader program once to populate test records.
  3. Reports & classesCreate each program via SE38 and each class via SE24, then activate.
  4. Smart FormBuild ZSF_PAYSLIP in SMARTFORMS, then the driver program.
  5. Module Pool screensBuild Screen 0100 for each program using Screen Painter (SE51) and Menu Painter (SE41).
  6. Transaction codeCreate ZPAYROLL in SE93, pointing to the main navigation program and screen.
  7. Advanced objectsCDS view, exception class, BAdI, authorization object, and RFC function module.
  8. TestRun ABAP Unit tests, then walk through the manual test case log.
